# lib/gto: game theory for the Lab

Pure TypeScript with no DOM and no dependencies beyond `lib/poker`, so it runs unchanged in a Web Worker. Everything is deterministic: the solvers use no randomness and the variance simulator takes a seed.

| File | What it does |
|---|---|
| `game.ts` | Game trees (chance / decision / terminal), `createGame`, profiles, exact `expectedValue`, `bestResponse`, `exploitability` |
| `cfr.ts` | `createCfrSolver`: vanilla CFR and CFR+, steppable in chunks |
| `kuhn.ts` | Kuhn poker tree, info-set keys and the mapping to OpenSpiel strings, Kuhn's analytic equilibrium family |
| `akq.ts` | The [A,K,Q] half-street game for any pot P and bet B: tree, closed form, summary of any profile |
| `preflop-matrix.ts` | Loads the precomputed 169x169 heads-up preflop matrix (`n_ij`, `E_ij`) |
| `data/preflop-matrix.ts` | The matrix itself, generated by `scripts/build-preflop-matrix.ts` (do not edit) |
| `pushfold.ts` | Heads-up push/fold Nash by CFR+ on the matrix, exact exploitability, 13x13 grid and range-text helpers |
| `variance.ts` | Win-rate variance simulator with analytic comparisons and drawdowns |
| `scripts/` | Matrix build, Kuhn export and the OpenSpiel cross-check (test-only, never bundled) |

## Conventions

- **Units.** Kuhn and AKQ payoffs are in chips; push/fold and variance are in big blinds.
- **Players.** Players are 0 and 1, and tree payoffs are to player 0 (zero-sum). In Kuhn, player 0 acts first. In AKQ, player 0 is X (the checker) and player 1 is Y (the bettor).
- **Profiles.** A profile is one `Float64Array` with a probability per action for every info set, starting at `InfoSet.offset`. `profileToMap` / `profileFromMap` convert to and from `{ infoSetKey: number[] }`.
- **Exploitability.** NashConv = the sum over both players of (best-response value − value under the profile). In a zero-sum game the values cancel, so NashConv = BR₀ + BR₁. **Exploitability = NashConv / 2**, which is OpenSpiel's convention. Both are computed exactly by best response on the tree, with no sampling. Best responses are chosen per info set, because the responder can't see the opponent's cards, and the deepest info sets are resolved first.
- **Hand classes.** Class index *i* is the position in `HAND_CLASSES` from `lib/poker`: row-major over the standard 13x13 grid with ranks A..2 from the top-left, so 0 = AA, 1 = AKs, 13 = AKo, 14 = KK and 168 = 22. Pairs sit on the diagonal, suited hands above it and offsuit hands below it. `classGrid(freq)` reshapes a 169-vector into that grid.

## CFR

`createCfrSolver(game, { variant })` returns `{ iterations, step(n), currentStrategy(), averageStrategy(), report() }`. `report()` gives the exact value, NashConv and exploitability of the average strategy. A worker can call `step(500)`, post `report()`, and repeat.

- `"cfr"`: vanilla CFR (Zinkevich et al. 2007) with simultaneous updates, regret matching and a uniform average.
- `"cfr+"` (the default): CFR+ (Tammelin 2014) with alternating updates, regret-matching+ and an average weighted linearly by iteration. On Kuhn poker it reproduces OpenSpiel's `CFRPlusSolver` to the last digit: same value and exploitability after 2,000 iterations.
- **No pruning on the opponent's zero-probability actions.** The average strategy is weighted by the player's own reach, so info sets the opponent has stopped reaching still need their strategy sums. An earlier version pruned those branches. In the AKQ game at P = B, X's calling frequency with an ace then froze at 50% and the result stayed exploitable.

## Kuhn poker

The rules are OpenSpiel's `kuhn_poker`: ante 1, J < Q < K, player 0 passes or bets 1. Our info-set keys are the card letter followed by the history (`p` = pass/fold, `b` = bet/call), for example `"Q"`, `"Kpb"` or `"Jb"`. Actions are always `[pass, bet]`, matching OpenSpiel's action ids 0 and 1. `toOpenSpielInfoState("Qpb") === "1pb"`, because OpenSpiel writes the card as 0/1/2. This format was checked against pyspiel's `TabularPolicy.state_lookup`.

`kuhnEquilibriumBetProbs(alpha)` / `kuhnEquilibriumProfile(game, alpha)` give Kuhn's family for α ∈ [0, 1/3]. Player 0 bets J with α, checks Q, bets K with 3α, and after pass-bet calls Q with α + 1/3. Player 1's strategy is unique: call a bet with Q at 1/3 and with K always; after a pass, bet J at 1/3 and K always. The value is −1/18 throughout. `kuhnAlpha` reads off which α a solved strategy landed on.

## AKQ game

Each player holds one card of A > K > Q. Each player is treated as having put P/2 into the pot, so the payoffs are zero-sum. Y's "pot share" (Chen & Ankenman's convention, with the pot treated as dead money) is P/2 + Y's value.

`akqClosedForm(P, B)` derives the equilibrium. For **P > B** it is unique:

| Quantity | Formula | B = 1 |
|---|---|---|
| Y bluffs Q | β = B / (P + B) | 1 / (P + 1) |
| X calls with K | c = (P − B) / (P + B) | (P − 1) / (P + 1) |
| X's total call vs the bluffer (A always, K at c) | (1 + c)/2 = P / (P + B) = MDF | P / (P + 1) |
| Bluffs as a share of Y's bets | β / (1 + β) = B / (P + 2B) | 1 / (P + 2) |
| Value to Y per deal | B (P − B) / (6 (P + B)) | (P − 1) / (6 (P + 1)) |

For **B ≥ P**, a bluff loses B to the ace and wins at most P from the king, so K never calls and the value is 0. At P = B any bluffing frequency in [0, 1/2] is an equilibrium, and Y's ace is indifferent between betting and checking.

**What this means for RESEARCH.md's row** ("bluff Q at 1/(P+1); call K at P/(P+1); pot-sized bet → both 50%"):
- "Bluff Q at 1/(P+1)" holds exactly.
- "Call K at P/(P+1)" needs rewording. P/(P+1) is X's **total** calling frequency against the bluff (the ace always calls, the king at (P−1)/(P+1)). The king's own frequency is (P−1)/(P+1).
- "Pot-sized bet → both 50%" is half right. With a pot-sized bet, X's total call is 50% but the king **never** calls. Y's 50% bluff frequency is only the top of the equilibrium interval [0, 50%], because Y's bluff is break-even whenever K folds.

CFR+ agrees with the closed form to better than 1e-3 in every frequency, and to 1e-4 in value, at (P, B) = (2,1), (1,0.5), (3,1), (10,1), (1.5,1) and (4,3) after 5,000 iterations.

## Heads-up push/fold

The game: SB posts 0.5, BB posts 1, there is no ante, and both stacks are S bb including the blind (S ≥ 1). SB folds (−0.5) or shoves. BB folds (SB +1) or calls (SB nets 2S·E − S). Class pairs are weighted by `n_ij / 1,624,350`, which accounts for card removal. `E_ij` is the exact all-in equity of SB class *i* against BB class *j*, averaged over those combo pairs.

SB's value is bilinear in the push vector *s* and the call vector *c*, so both best responses are exact and cheap: push class *i* iff its push gain is positive, and call class *j* iff its call gain is positive. NashConv = max over *s* of u(s, c) − min over *c* of u(s, c), in bb.

The solver is CFR+ on the 169 + 169 one-shot info sets: regret-matching+, alternating updates and linear averaging. Each iteration costs two 169x169 matrix-vector products. It was chosen over fictitious play because the CFR+ average converges roughly like 1/T here, while fictitious play converges more like 1/√T and oscillates.

```ts
solvePushFold(stack, { targetNashConv = 1e-5, maxIterations = 20000, checkEvery = 50 }?) → PushFoldReport
  // { stack, push: Float64Array(169), call: Float64Array(169), sbValue, bestResponseValues,
  //   nashConv, exploitability, pushFraction, callFraction, iterations }
createPushFoldSolver(stack) → { stack, iterations, step(n), averageStrategy(), report() }   // for streaming progress
pushFoldExploitability(stack, push, call) → PushFoldReport                                 // grade any strategy pair
classGrid(freq) → number[13][13];  CLASS_GRID_NAMES;  rangeText(freq, threshold = 0.5) → "22+, A2s+, ...";  comboFraction(freq)
```

`pushFraction` and `callFraction` are combo-weighted shares of all 1326 hands.

### Rebuilding the matrix

```
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --import ./lib/poker/scripts/register-ts.mjs lib/gto/scripts/build-preflop-matrix.ts
```

The script enumerates every card-disjoint combo pair with SB class < BB class, 808,392 pairs in all. It maps each pair to the smallest encoding over the 24 suit relabellings and both seat orders, which leaves 46,683 distinct matchups. It runs `exactEquity` from `lib/poker` (all 1,712,304 boards) on each matchup, spread across `node:worker_threads` cores, and then averages back into classes. Equity sums to 1 between the two players, so E_ji = 1 − E_ij, and E_ii = 1/2 exactly.

The data file stores only the upper triangle, as base64: E·10⁹ as little-endian Uint32 and n_ij as Uint8. The file is 104,623 bytes. The app decodes it once, in about 3 ms, through `preflopMatrix()` and never recomputes it. The last build took 843 s on 8 worker threads.

The tests check the stored matrix in four ways:
- n_ij is symmetric, matches live combo counting, and sums to 1,624,350.
- E_ij + E_ji = 1.
- Known equities come out right: AA vs a random hand 85.2%, 32o 32.3%, AA vs KK 81.95%.
- Seven class pairs, recomputed live with `exactEquity`, agree to 1e-8.

## Variance simulator

`simulateVariance({ winRate, stdDev, hands, runs, seed?, samplePaths? = 5, pathPoints? = 200, histogramBins? = 40 })`. Each hand is an independent normal draw with mean winRate/100 bb and SD stdDev/10 bb, so 100 hands have mean `winRate` and SD `stdDev`. Hands are simulated one at a time, so drawdowns are measured at hand resolution. Speed is about 25 ns per hand: 1,000 runs × 50,000 hands take 1.2 s in Node.

It returns `finals` (one result per run), a `histogram`, sample `paths` plotted at `pathHands`, and `simulated` and `analytic` summaries. Each summary has the mean, the SD, the fraction of runs below zero and a 95% interval. The analytic values are mean = wr·H/100, SD = sd·√(H/100), P(below 0) = Φ(−mean/SD) and the interval mean ± 1.96 SD. The result also gives max-drawdown stats: mean, median, 95th percentile and max.

The tests compare the simulation with the analytic values to within 4 standard errors:
- SE(mean) = σ_F/√R
- SE(SD) ≈ σ_F/√(2(R−1))
- SE(p) = √(p(1−p)/R)

## Running

- `npm test` includes all `lib/gto` tests.
- **OpenSpiel cross-check.** This is test-only. OpenSpiel is Apache-2.0, runs from Python, and is never vendored or bundled.
  ```
  node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --import ./lib/poker/scripts/register-ts.mjs lib/gto/scripts/kuhn-export.ts > kuhn-policy.json
  python lib/gto/scripts/kuhn_openspiel_crosscheck.py kuhn-policy.json
  ```
  The script loads our CFR+ average policy into an OpenSpiel `TabularPolicy`. It prints OpenSpiel's exploitability and expected value for that policy, plus OpenSpiel's own CFR+ result. It fails unless the value is −1/18 ± 1e-3 and the exploitability is below 1e-3.
